## 项目结构

```text
public/          浏览器前端、PDF.js、KaTeX 与静态资源
desktop/         Rust 桌面窗口、本地服务、EXE 与安装器构建
desktop/installer/ Inno Setup 安装向导与安装模式标记
server.js        Node.js 开发服务
security.js      Node 服务的请求与路径边界
model-profiles.js 模型配置管理
test/            单元、浏览器与桌面回归测试
docs/            使用说明与贡献者参考
.github/         自动检查、Issue 和 PR 模板
```

`data/`、`papers/`、构建目录、测试产物和私人资料不进入仓库。

## 浏览器开发

建议使用 Node.js 24 LTS。服务仅依赖 Node 内置模块，前端无需打包。

```powershell
git clone https://github.com/975952/prt.git
cd prt
New-Item -ItemType Directory -Force test/artifacts/dev/data, test/artifacts/dev/papers
$env:PRT_DATA_DIR = "$PWD/test/artifacts/dev/data"
$env:PRT_PAPERS_DIR = "$PWD/test/artifacts/dev/papers"
$env:PORT = "8899"
node server.js
```

浏览器打开 `http://127.0.0.1:8899`，导入测试 PDF。此配置把开发数据隔离到测试目录；结束后在终端按 Ctrl+C。窗口平铺、系统窗口恢复等桌面功能需要 EXE 验证。

## Windows 桌面构建

准备 Windows x64、[Rust stable 的 MSVC 工具链](https://rustup.rs/)、Visual Studio Build Tools 的“使用 C++ 的桌面开发”与 Windows SDK，以及 WebView2 Runtime。首次构建需要下载 crates。

在仓库根运行：

```powershell
cmd /d /c desktop\build.bat
```

产物为仓库根的 `prt.exe`，脚本还会尝试同步到桌面并核对 SHA256。运行中的旧程序不会被强制关闭；如果文件被占用，按提示退出对应副本后重试。

`public/` 在构建时内嵌到 EXE。每次修改前端，包括新增文件，都应使用上述脚本重新构建；仅刷新页面或直接启动旧 EXE 不会更新内嵌资源。

安装包另需 [Inno Setup 6](https://jrsoftware.org/isinfo.php)。从仓库根运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File desktop/build-setup.ps1
```

安装包产物写入 `dist/`，不进入 Git。安装版通过 `prt-installed.flag` 使用标准用户目录；便携版保持相邻目录布局，Node 开发服务的路径契约不变。安装、迁移和卸载测试必须使用独立 AppId、隔离安装路径与 `PRT_DATA_DIR` / `PRT_PAPERS_DIR`，不能触碰实际安装或私人资料。

### 应用内更新

桌面版启动时自动检查发布版本，更新操作从“设置 → 应用更新”发起。下载产物须通过 `SHA256SUMS.txt` 校验；安装版通过静默覆盖安装更新，便携版替换原位置的 EXE，保留原有数据路径。更新前复用所有窗口的保存与退出流程，只有全部窗口成功保存并退出后才允许辅助进程覆盖程序并重新启动。检查、下载、校验或保存失败应保留当前版本并提供重试。

Node 开发服务显示不支持自更新的说明，不访问外部发布服务，也不启动安装器。旧版没有更新入口时，首次运行新安装包即可覆盖升级，无需先卸载；后续版本使用应用内更新。

## 测试

### 基础检查

```powershell
npm --prefix test test
```

无需安装依赖或启动服务，运行 Agent 工具循环、输出排版边界、草稿状态、翻译队列、双栏选区、提示词一致性和仓库文档检查。GitHub Actions 在 Windows 与 Linux、Node.js 24 上执行相同入口。这些检查不等同于完整桌面验收。

### 浏览器与 EXE 回归

```powershell
npm --prefix test ci
node test/reader-layout.mjs
node test/product-ux.mjs
node test/theme.mjs
node test/updater-ui.mjs
```

上述套件自行启动隔离 Node 服务并在结束后关闭。默认使用 Windows 上的 Edge；其他安装位置可先设置 `$env:CHROME = 'C:/path/to/chrome.exe'`。

重新构建后，使用相同的交互检查验证桌面内嵌资源：

```powershell
node test/reader-layout.mjs --desktop
node test/product-ux.mjs --desktop
node test/theme.mjs --desktop
node test/cross-file-chat.mjs --desktop
node test/session-background.mjs --desktop
node test/session-regeneration.mjs --desktop
```

这些测试从隔离 EXE 服务加载页面，用 Edge 自动化验证。原生 WebView2 窗口行为需另跑 `node test/multiwindow.mjs`，不能以浏览器检查替代。

`updater-ui.mjs` 使用隔离服务与模拟更新响应，验证自动检查、设置入口、下载状态与失败重试，不访问真实发布服务，也不替换用户程序。UI 检查不能代替真实安装包的下载校验、全部窗口保存退出、覆盖安装与重启验收；后者必须使用隔离安装目录和测试资料。

安装版与便携版的存储、旧版导入、安装升级和卸载保留数据使用以下隔离检查：

```powershell
cargo test --manifest-path desktop/Cargo.toml --locked
node test/storage-cli.mjs
node test/installer.mjs
```

安装器检查需要 Inno Setup 6，使用随机 AppId、独立快捷方式与测试目录。若已下载旧版便携 EXE，可为两个 Node 套件添加 `--previous-exe path/to/prt.exe`；安装器套件同时添加 `--previous-version 1.2.13`，验证真实旧版升级与占用保护。

跨文件套件使用真实合成 PDF 和可控延迟，覆盖提交、读页、工具、流输出、附件恢复与保存时的切换。持久化套件在 Node/Rust 上共用相同样本，并通过实际 HTTP 验证旧快照、重生成、改名、删除与清空的并发行为。源码对应检查可去掉 `--desktop`；Node 持久化 HTTP 检查使用 `--http`。

部分旧端到端套件依赖预先启动的桌面测试服务，按文件头说明使用 `node test/desktop.mjs`，结束后用 `node test/desktop.mjs --stop` 清理测试实例。不要将测试指向真实阅读器端口。

## 修改与发布

- Node 和 Rust 共同实现的接口应保持输入、错误及持久化语义一致。
- 自动化仅使用隔离数据、公开或合成 PDF、模型替身。真实模型检查需明确记录服务和覆盖范围。
- 新增源码入口时同步 `test/pack.mjs` 的白名单。`node test/pack.mjs` 可生成并验证源码包。
- 修改提示词时同步版本、快照和[提示词参考](prompts.md)；界面翻译约定见[界面语言](internationalization.md)。
- 发布前更新 [CHANGELOG.md](../CHANGELOG.md)、重新构建、验证 EXE，核对下载产物与 SHA256；不要仅更新截图就宣称功能已发布。
- [发布工作流](../.github/workflows/release.yml) 构建安装包、便携 EXE、源码包与校验文件；发布前需确认 tag 与 Cargo 版本一致，并检查安装、升级、旧版导入及卸载保留数据。历史下载仅保留重要版本，Git 标签与变更记录保留源代码回溯。

文档中的 API Key 只用明显的占位值。`.bat` 保持 ASCII，其他文本使用 UTF-8；提交前检查暂存路径与内容。
